# WebhookSink

<div align="center">
  <img src="./client/public/logo.svg" alt="WebhookSink Logo" width="120" />
</div>

**WebhookSink** is a modern, real-time webhook inspection and receiving tool. It allows you to create isolated webhook endpoints ("inboxes"), define mandatory validation rules, and monitor incoming requests instantly in a beautiful React dashboard.

## 🚀 Features

- **Real-Time Feed:** See incoming webhooks appear instantly without refreshing, powered by Socket.io.
- **Dynamic Validation:** Enforce specific HTTP Methods, Query Parameters, and Headers. Invalid webhooks are flagged and rejected with a `400 Bad Request`, but still logged for debugging.
- **Custom Responses:** Configure exactly what JSON response your webhook sender receives upon a successful request.
- **Robust Logging:** Built-in Winston and Morgan logging for deep server-side HTTP request and error tracking (`server.log` and `error.log`).
- **High Performance:** Uses Redis for lightning-fast memory storage of configurations and incoming payloads.

## 🛠️ Tech Stack

- **Frontend:** React 19, Vite, TailwindCSS, React Router, Socket.io-client.
- **Backend:** Node.js, Express, Socket.io, Redis, Winston, Morgan.

## 📋 Prerequisites

- **Node.js** (v20+ recommended)
- **Redis Server** (must be actively running on `localhost:6379`)

## 📦 Installation & Setup

1. **Clone or download the repository**, and open your terminal in the root directory.

2. **Install all dependencies:**
   The root `package.json` contains a script to install dependencies for the root, server, and client simultaneously.
   ```bash
   npm run install:all
   ```

3. **Start the application:**
   This will run both the Vite React frontend and the Express Node backend concurrently.
   ```bash
   npm start
   ```

4. **Access the Application:**
   - **Frontend UI:** [http://localhost:5173](http://localhost:5173)
   - **Backend API:** [http://localhost:3001](http://localhost:3001)

## 📡 Sending a Test Webhook

Once you create an Inbox from the UI, you'll be given a unique URL (e.g., `http://localhost:3001/webhook/<uuid>`).

You can test it using cURL. If you use Windows PowerShell, use `Invoke-RestMethod` or specify `curl.exe`:

```bash
curl.exe -X POST "http://localhost:3001/webhook/<uuid>" \
     -H "Content-Type: application/json" \
     -d "{\"event\": \"test\", \"status\": \"active\"}"
```

*(Note: If you configured mandatory headers or query params, be sure to include them in your request!)*

## 🐳 Deployment

WebhookSink is fully containerized and production-ready. A multi-stage `Dockerfile` is included to build both the frontend and backend into a single lightweight image.

### Docker Compose
For a simple single-server deployment, use the provided `docker-compose.yml` which spins up both the app and a Redis instance automatically:

```bash
docker-compose up -d --build
```
Access the application at `http://localhost:3001` (or your server's IP).

### Kubernetes
A complete manifest is provided in `k8s.yaml`. It sets up internal Redis pods and exposes the WebhookSink UI via a LoadBalancer on port 80.

```bash
kubectl apply -f k8s.yaml
```
*(Make sure to update the image registry in the YAML if you are pushing to a remote container registry.)*
